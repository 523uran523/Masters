# Masters 2.0 — реконструкция интерфейса

Здесь лежит техническое задание на реконструкцию Masters 2.0 и визуальный
референс к нему.

| Файл | Что это | Статус |
|------|---------|--------|
| `Masters_2_TZ.md` | Основное ТЗ: цель, дизайн-система, навигация, формы, экраны, настройки, этапы 0–7, сценарии приёмки U01–U20 | Принято в проект, реализация не начата |
| `Masters_2_reference.html` | Автономный HTML-прототип: 4 темы, навигация, демонстрационные карточки и формы | Только визуальный ориентир, не приложение |

## Правила работы

- **Приоритет у ТЗ.** При расхождении HTML и `Masters_2_TZ.md` действует ТЗ и
  подтверждённые правила учёта. Расхождение согласуется до реализации.
- **HTML — не источник бизнес-логики.** В прототипе вымышленные данные,
  упрощённые формулы, неполные вторичные экраны; вложения, экспорт, импорт и
  синхронизация не подключены. Демонстрационные значения и формулы нельзя
  переносить в production.
- **Учётное ядро сохраняется.** Не переписывать работающие расчёты ради
  редизайна: `MastersStore`, репозитории, SQLite, `payroll_engine.dart`,
  `document_service.dart`, синхронизация и существующие правила денег остаются.
- **Новые таблицы — только с миграцией.** Схема v26 не меняется ради цветов и
  компоновки. Черновики, шаблоны и пользовательские поля требуют отдельной
  версии схемы, backup/restore и тестов.
- **`kSyncedTables` не трогать автоматически.** `pay_conditions`, `payslips`,
  `accrual_entries`, `work_sessions`, вложения и аудит не синхронизируются;
  включать их можно только после отдельного протокола согласованности.
- **Старые ведомости v25/v26** остаются «предварительно, требует сверки» и не
  выдаются за подтверждённые.

## Этапы (из ТЗ, раздел 11)

| Этап | Результат |
|------|-----------|
| 0. Аудит | Матрица «старое → новое», проверка backup/restore |
| 1. Основа | Токены 4 тем, компоненты, доступность |
| 2. Навигация | RootShell, адаптивная оболочка, меню, настройки вкладок |
| 3. Формы | Заказ, клиент, позиция, операции, общий picker и строки |
| 4. Экраны | Работа, финансы, ресурсы, карточки, команда, аналитика |
| 5. Настройки | Новая карта, онбординг, персонализация |
| 6. Расширения | Шаблоны, черновики, пользовательские поля |
| 7. Релиз | Регрессия, реальный UI/PDF, подписанный APK |

Будущие Э6 `warranty-service`, Э7 `team-shifts`, Э8 `owner-analytics` и идеи
Positive Vector не входят в обязательный редизайн и выполняются отдельными
этапами. Реестр задач — `docs/specs/_queue.md`.
