## 2. Батчи (порядок исполнения)

### Б0 — критическое (сейчас)
1. **Mojibake-фикс** 3 файлов + regression-тест скан + git-археология (кто/какой коммит ввёл слом). ТЗ готово, выпущено.
2. **Статус релиза 0.3.7+10**: проверка серверного endpoint + APK на диске + git log. Если не опубликован — публикуем ПОСЛЕ B0-1 (реалистичнее: выпустим 0.3.8+11 со всеми фиксами, а 0.3.7+10 не трогаем).

### Б1 — Калькулятор v2 (5, 6, 9, 17, 18)
- Единицы: dropdown (CupertinoActionSheet/PopupMenu) вместо кнопок: шт, г, кг, л, см, м; «цена за»: шт / г / 100 г / кг / л / см.
- Per-job persistence: DB v15 `jobs.calculator_state TEXT (JSON)` — строки расчёта (ресурсы, работа, кол-ва, цены, единицы) сохраняются при каждом изменении; повторное открытие заказа восстанавливает состояние.
- Двусторонняя связь со складом: инвентарь-позы отображаются в «предлагаемых ресурсах»; сохранение нового ресурса создаёт позицию на складе (попапулн: имя, ед., остаток 0); выбор склада-позиции подставляет строку в калькулятор с остатком в подсказке.

### Б2 — Главная/Today (3, 4, 7, 22)
- Таймер рабочего дня: play/stop с паузами за день; плей → выбрать заказ (из открытых) или «без заказа»; ставка часа запоминается в Settings (employee.hourRate / global), не вводить повторно; траты=часы×ставка видны в сводке дня.
- Быстрые действия: одна компактная точка «₽» на Today → лист быстрая продажа/расход (amount → счёта → ок) — без входа в Деньги.
- Карточка-сводка месяца: «Всего на счетах / Доходы / Расходы / Прибыль (−налог-резерв)», клик → Аналитика.
- Клик-пирограмма (mini, 2–3 сектора: доход/расход/прибыль) на Today → Stats.
- Fix overflow в Stats/разделах (20): `FittedBox`/`Flexible`/`TextOverflow`, проверка длинных кириллических подписей.

### Б3 — Заказы (10, 16, bulk, QA)
- Настройки → Поля и возможности → «Канбан: колонки» — чекбоксы показа колонок (Новые / В работе / Ждёт ресурсов / Готово / Закрыто); kanban рендерит только включённые. ✅ сделано (99628af, подтянуто вперёд — конфликт с Б0 отсутствовал).
- Статус: дефолт «Новая»; в форме — dropdown (action sheet), кнопки убраны.
- Индикатор «не оплачен» у клиента и в списке долгов для закрытых заказов с долгом.
- Bulk-режим: выделение заказов (мульти-чек), действие «Слить в один» (титул/клиент/суммы суммируются, теги объединяются; исходные уходят в «Закрыто» с пометкой).
- QA: поиск-лупа в Заказах реально фильтрует по названию/тегам/клиенту/исполнителю; быстрый заказ + инлайн-клиент.

### Б4 — Деньги/операции (15)
- «Возврат» вместо void: по операции создаётся новая связная транзакция обратного знака (тип «Возврат», ссылка `reverses_id`); исходная отображается серой со ссылкой; суммы/счета пересчитываются; аудит-запись. Если операция уже отменена/возвращена — повторный возврат недоступен.

### Б5 — Настройки и режимы (13, 21, 23)
- Тумблер «Команда и зарплата» — скрывает раздел сотрудников/з/п и связанные кнопки в Деньгах (соло-режим).
- Тумблер «Калькулятор расходов» — скрывает вход в калькулятор из заказа.
- Реорганизация настроек: блок 1 — общие возможности (теги, канбан-колонки, таймер, калькулятор, команда) компактными окнами; блок 2 — приложение (тема, язык/термины, PIN/биометрия, бэкапы/экспорт-импорт, обновления) в стандартном порядке.
- «Собрать стандартную конфигурацию» — пресеты (соло-мастер / мастер+бригада / мастер+клиенты-записи) → ставят нужный набор чекбоксов.

### Б6 — Большой продуктовый блок (19, 23)
- Регистрация: вопрос «вы работаете с заказами, с записями или оба».
- Объединённый график: один kanban с сущностью «событие» (заказ/запись как тип-тег), переключение kanban ↔ календарный вид; запись доступна не всем — по выбранной конфигурации.
