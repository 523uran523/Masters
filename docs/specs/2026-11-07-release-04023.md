## Состав релиза

### §1.1 Автобэкап перед миграцией (app_database.dart)
- В `onConfigure` читается `PRAGMA user_version`; если 0 < v < 22 —
  ставится `needsBackup`, выполняется `PRAGMA wal_checkpoint(TRUNCATE)`
  (иначе копия файла теряет WAL-данные).
- В `onUpgrade` первой операцией `_writePreV22Backup(resolved)` → копия
  в `backups/pre_v22_<ms>.db`; ошибка копирования не блокирует апгрейд.
- После успеха: `_markBackupMigrated()` (переименование в `.migrated.db`),
  `_pruneOldBackups()` (удаление помеченных старше 7 дней).
- При падении: `_restoreFromPreV22Backup()` — удаляет `-wal`/`-shm`,
  копирует последнюю копию, открывает БЕЗ `version`, возвращает
  `AppDatabase(migrationHalted: true)`.
- Тестовые хуки: `AppDatabase.testHaltHook` (void Function(int oldVersion),
  вызывается в onUpgrade после бэкапа), `AppDatabase.backupsDirectoryOverride`
  (path_provider недоступен в unit-тестах).
- `migrationHalted` проброшен: `main.dart` → `MastersApp(migrationHalted:)`
  → `_MastersAppState` post-frame после `_ensureAppPinIfNeeded()`
  → `_showMigrationHaltedAlert()` (showAppAlert, импорт `ui.dart` добавлен
  в app.dart — циклов нет, ui.dart импортирует только cupertino+тему).
- `dart:io` в `app_database.dart` допустим — уже есть в
  `update_service.dart`, `masters_store.dart` и др., web-сборка работает.

### §1.2 Legacy-платежи (jobs.legacy_paid + бэкфилл)
- Колонка `jobs.legacy_paid INTEGER NOT NULL DEFAULT 0` добавлена в
  `_ensureFoundationColumns` (НЕ в hotfix — бэкфилл v22 пишет в неё).
- `_backfillJobObligations` переписан: пул legacy-оплат грузится ОДНИМ
  запросом до цикла батчей (`GROUP BY client_id`, `job_id IS NULL`,
  фильтр voided без алиаса), FIFO-распределение по заказам клиента
  (uncovered = price−paid, берём min(pool, uncovered)); заказ, закрытый
  из пула → `legacy_paid=1`, obligation не создаётся; иначе obligation
  с paidCents=totalPaid.

### §1.3 Таблица attribute_types + UI-типизация
- Таблица в `_createFoundationSchema`: `attribute_types (key TEXT PK,
  value_type TEXT DEFAULT 'text', entity_type TEXT, label TEXT DEFAULT '',
  created_at INTEGER)` — БЕЗ options (соответствует ТЗ §1.3).
- `_seedAttributeTypes` (INSERT OR IGNORE, entity_type='*'): size(text),
  weight(number), color(text), flavor(text), quantity(number),
  due_date(date), tier_count(number), diameter(number), serving(number),
  category(text). Boolean/boolean и select УБРАНЫ (модель поддерживает
  только text/number/date).
- Вызовы: в `_createSchema` после `_createFoundationSchema`, и в блоке
  `oldVersion < 23 && newVersion >= 23` (`_ensureHotfixColumns` +
  `_seedAttributeTypes`).
- `_ensureHotfixColumns`: `money_transactions.payment_method TEXT`,
  `obligations.payment_method TEXT`.
- `version: 23` в `openDatabase`.
- `schema_tables.dart`: `attribute_types` добавлен только в
  `kBackupApplyOrder` и `kBackupTables` (BackupTable('attribute_types',
  'attribute_types')); НЕ в kSyncedTables/kAuditedTables (нет
  device_id/updated_at — триггеры упали бы).
- Модели: `attribute_type.dart` (AttributeType: key, valueType text/number/
  date, entityType item/job/client/*, label, createdAt; методы
  `parse(raw)` → AttributeValue{text,num,display} или null при невалидном;
  `formatHint`; `_isIsoDate` дд.мм.гггг; AttributeValue) и
  `attribute_type_repository.dart` (getAll, save REPLACE).
- В `masters_store.dart`: `_attributeTypes` + загрузка
  `_attributeTypeRepo.getAll()` в `load()`, `attributeTypesOf()`,
  `attributeType()`, `setAttributeValue()` (типизированная запись
  с валидацией по типу).
- UI в шитах: `catalog_screen.dart` `_addAttribute()` → `setAttributeValue`
  с catch FormatException, `job_form_screen.dart` `_addAttribute()` →
  `setAttributeValue` с catch FormatException.

### §1.4 payment_method в UI оплаты
- `money_transaction.dart` и `obligation.dart` — поле `paymentMethod` +
  toMap/fromMap/copyWith (obligation — есть; money_transaction — toMap
  тоже добавлен).
- Стор: `addTransaction({..., String? paymentMethod})` (trim/empty→null),
  `payObligation(..., String? paymentMethod)` — пишет в obligation.copyWith
  и передаёт в addTransaction.
- Общий виджет: `ui.dart` — `showPaymentMethodPicker()` + `kPaymentMethods`
  (cash=Наличные, kaspi=Kaspi, card=Карта, transfer=Перевод).
- `money_screen.dart`: `_payObligationFlow` вызывает
  `showPaymentMethodPicker(context)`, `paymentMethod` пробрасывается в
  `store.payObligation()`, отображение в деталях транзакции (_KV).
- `job_detail_screen.dart`: `_acceptPayment` и `_closeJob` — оба
  вызывают `showPaymentMethodPicker(context)`, `paymentMethod` пробрасывается
  в `payObligation` и `addTransaction`.
- `version: 23` в `openDatabase`.

### Критерий «5 минут» (quick_start_test)
- `recalcJobTotals` теперь вызывает `syncJobObligations`: раньше обязательство
  заказа оставалось с суммой из пустой формы, и «Принять оплату» предлагало
  устаревший остаток.
- `test/quick_start_test.dart` — 3 теста: путь клиент → заказ → позиция
  каталога → оплата → закрытие укладывается в 5 действий стора; заказ с
  частичной оплатой закрывается и остаётся в дебиторке; маржа пустого
  заказа нулевая.

## Риски и ограничения
- Основной сервис не поддерживает `HEAD` и игнорирует `Range` —
  докачка не работает, но контрольная сумма после полной загрузки сходится.
- `min_supported_version_code` = 1, форс-обновления нет.
- Схема v23 (hotfix-колонки) аддитивна: `ALTER TABLE ADD COLUMN`,
  `CREATE TABLE IF NOT EXISTS` — никаких DROP/RENAME.
- `payment_method` в UI — ChipButton в шитах оплаты заказов и денег;
  старые транзакции без метода отображаются как «—».
