# ТЗ: адаптивные колонки Kanban в настройках (jobs-config slice 1)

Статус: **выдано** (senior)
Дата: 31.10.2026

## Цель
Пользователь: «в настройках надо иметь возможность убрать лишние поля канбана, если они не нужны (например, Готово и Ждёт ресурсы)… надо адаптивно сделать в настройках самой программы».

Настройка показа колонок kanban-вида в Заказах: какие статусы отображать как колонки выбираются чекбоксами в Настройках.

## Входит / не входит
- Входит: тумблеры/чекбоксы по статусам в Настройках, адаптивный рендер kanban (только включённые колонки), дефолт = все текущие статусы.
- Не входит: дропдаун статуса (отдельный слайс, т.к. трогает job_detail_screen — сейчас занят другой задачей), bulk-выбор, изменение статуса в форме.

## Файлы (только они)
- `lib/state/settings_controller.dart` — новый ключ `kanban_columns` (StringList; null/пусто = все статусы включены), getter `kanbanColumns` + `setKanbanColumns(List<String>)`, notifyListeners.
- `lib/features/settings/settings_screen.dart` — в существующую структуру (секция по разделам, групповые панели) добавить секцию «Заказы → Канбан»: список чекбоксов по каждому статусу (текущие значения JobStatus/константы статусов — взять из кода jobs_screen; не хардкопить строки заново, вынести общий список констант, если отсутствует — например, в `lib/features/jobs/job_constants.dart` или куда решит senior, если константы уже есть — использовать их).
- `lib/features/jobs/jobs_screen.dart` — kanban-вид рендерит только включённые колонки; если включено меньше двух колонок — канбан всё равно работает (одна колонка ок). Список-вид не затрагивается. Фильтр по статусу, если он ссылается на скрытую колонку, не ломается (скрытая колонка = не показывается в kanban, заказы с таким статусом видны в списке).
- Допустим один новый файл с константами статусов, если таковых нет.

## Критерии приёмки
- В настройках можно включить/выключить каждую колонку; kanban сразу показывает только выбранные.
- Перезапуск — состояние сохранено (SharedPreferences).
- Дефолт (ключ не задан) — все колонки, как сейчас.
- `flutter analyze --no-pub` 0 ошибок; `flutter test` зелёные.
- Один commit: `Add kanban column visibility settings`, stage только затронутые файлы, push main (перед push: `git pull --rebase origin main`, т.к. параллельно идёт другая задача в этом репо).
