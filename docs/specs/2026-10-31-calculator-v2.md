# ТЗ: Калькулятор расходов v2 (юниты + персистентность + склад)

Статус: **не выпущено** (ждёт: mojibake-encoding-fix — правится masters_store.dart; затем эта задача)
Дата: 31.10.2026
Пользовательские заметки: №5, 6, 9, 17, 18.

## Цель
Сделать калькулятор стоимости заказа пригодным по реальным юзеркейсам:
1. Единицы измерения по выпадающим спискам, включая **литры и сантиметры** (сейчас только шт/г/кг, кнопками).
2. Состояние калькулятора **запоминается по заказу** — выход из него не стирает введённое; всегда можно вернуться и отредактировать.
3. **Двусторонняя связь со складом**: ресурс, введённый в калькуляторе, можно сохранить на склад; позиции склада предлагаются в качестве ресурсов; выбор позиции склада подставляет её в строку расчёта.
4. Визуальные пометки «+ / −» возле валюты в строках цена/расход (замечание №9).

## Входит
### А. Единицы (cost_calculator_screen.dart)
- Выпадающие списки (CupertinoActionSheet или PopupMenu) вместо кнопочных групп:
  - «Ед. изм.» количества: шт, г, кг, л, см, м, м²
  - «Цена за»: за шт, за 100 г, за кг, за л, за м, за см (для «г»/«см» — без «за 100 г», только за единицу; логика перевода в базовую единицу сохраняется и расширяется: л=1000 мл не вводится, базовые: шт=шт, г→кг, л→л, см→м (0.01), м→м, м²→м²).
- Итоги расчёта в «базовой валюте стоимости» не нужны: сумма строки = qty × price-per-unit с учётом выбранного «за» (формула текущая, расширяется на новые единицы — без кривых переводов: «за л» не приводится в кг и т.п.; каждая строка считает свою стоимость сама).
- «+ / −»: у поля цены — иконка «+» (у дохода/цены продажи), у итогового расхода строки — «−» (расход). Рядом с символом валюты, компактно.

### Б. Персистентность (DB v14→v15)
- `lib/data/app_database.dart`: `ALTER TABLE jobs ADD COLUMN calculator_state TEXT` (guarded, oldVersion < 15).
- JSON-состояние: строки ресурсов (name, qty, qtyUnit, price, priceUnit, note) + строки работы (role, hours, rate) + версия схемы JSON.
- `lib/state/masters_store.dart`: `calculatorStateForJob(jobId)`, `saveCalculatorState(jobId, json)`; сохранение при закрытии калькулятора И при каждом изменении (debounce 400 мс или по кнопке — senior решит, но выход по back не должен терять данные).
- `cost_calculator_screen.dart`: при открытии — восстановление из состояния (пустой, если нет); из карточки/деталки заказа — повторный вход всегда редактирует то же состояние.
- Тесты: database_test (v15, migration v14→v15), store-тест сохранение/чтение состояния.

### В. Склад ↔ калькулятор
- В строке ресурса: кнопка «Сохранить на склад» → `store.createInventoryItem(name, unit, price, stock: 0)` (один раз на имя — если позиция уже есть, обновить цену? — решение: если есть — не создавать, только подменить значения строки из складной позиции).
- В шапке секции «Ресурсы»: выпадающий список позиций склада → выбор подставляет строку (название/ед./цена из позиции, остаток показывается серым рядом: «ост. 12 шт»).
- Изменили позицию на складе → предложение в калькуляторе обновляется (единый источник — store.inventoryItems).

- Новая версия приложения/релиз.

## Критерии приёмки
- Ед. изм. и «за» — только выпадающие списки; литры и см на месте.
- Закрыл заказ, перезапустил app, открыл калькулятор — всё, что ввёл, на месте.
- Новый ресурс из калькулятора появился на складе; позиция склада появилась в подборе ресурса.
- analyze 0 ошибок, тесты зелёные (включая migration v14→v15).
