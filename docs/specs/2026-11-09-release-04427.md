## Состав релиза

### Э4.1 Модель и репозиторий
- `lib/data/models/client_credit.dart` — поля строго по колонкам v22
  (`id, client_id, kind, title, amount_cents, remaining_cents, units_total,
  units_left, expires_at, status, note` + `deleted_at`/`device_id`),
  `isActive`, `isExpiredAt(now)`, `kindLabel`, `copyWith`/`toMap`/`fromMap`
  с маркером `_unset` (различает «не трогать» и «поставить null»).
- `lib/data/models/credit_change.dart` — читатель `audit_log`:
  `CreditChange.fromRow` разбирает `before_json`/`after_json`, `deltaCents` —
  изменение `remaining_cents`, `amountCents` — сумма операции по модулю.
  Таблицы движений **нет**: один источник правды — аудит (§12.1).
- `client_credit_repository.dart` — `getAll` / `forClient` / `getById` /
  `save` / `softDelete`.
- `AppDatabase.creditChanges({limit})` — выборка `entity='client_credit' AND
  action LIKE 'credit.%'` из `audit_log` (сортировка `at DESC, id DESC`).

### Э4.2 Стор: деньги клиента ≠ выручка
- `credits`, `clientCredits(clientId)`, `clientCreditById`, `creditChanges`,
  `creditHistory(creditId)`, `clientCreditTotalCents` (Σ `remaining_cents` по
  активным — обязательство), `deleteClientCredit` (soft-delete).
- `createClientCredit` — создаёт кредит **и** транзакцию `direction='in'`
  (категории Депозит/Абонемент/Сертификат по `kind`) + `audit('credit.create')`.
- `useClientCredit` — возвращает фактическую сумму списания:
  - **не создаёт** `money_transactions` (денег второй раз не приходило);
  - уменьшает `remainingCents` и `unitsLeft` (абонемент «тратит посещение»);
  - при `remaining == 0` ставит `status='used'`;
  - гасит обязательство заказа через `_applyJobPaymentToObligation(jobId, used)`;
  - пишет `audit('credit.use')`;
  - отказывает истёкшему кредиту (`!isActive` → 0).
- `refundClientCredit` — транзакция `direction='out'` + `audit('credit.refund')`,
  `status='refunded'` при полном возврате.
- `expireCredits()` — `status='expired'`, **баланс не трогает** (деньги
  остаются на руках до решения владельца), пишет аудит, возвращает число.
  Вызывается из `load()`, поэтому просрочка видна сразу после открытия БД.
- `clearAll` чистит `client_credits` до `clients` (FK `ON DELETE CASCADE`).

### Э4.3 Отложенная выручка: одна формула (§12.1)
- `deferredDeltaCents(from, to)` — Δ Σ `remaining_cents` за период по аудиту.
  `credit.refund` исключён: возврат уже учтён оттоком в `money_transactions`,
  иначе сумма вычлась бы дважды.
- `recognizedRevenueCents(from, to)` = Σ поступлений − Δ обязательств.
  Граница `to` **исключается** (`isBefore(to)`), чтобы соседние периоды не
  считали одну операцию дважды.
- `clientCreditRevenueCents(from, to)` — только списания (для разбивки в P&L).
- `stats_screen` больше **не считает выручку инлайн**: `revenue` и `revenuePrev`
  берутся из `store.recognizedRevenueCents(...)`. Дублирующий расчёт удалён —
  в П&Л депозит не превращается в выручку до оказания услуги.

### Э4.4 UI (§6.8)
- `lib/features/clients/client_credits.dart` (**новый**, `library;`):
  - `ClientMoneySection` — секция «Деньги клиента» в карточке: обязательство
    (orange при >0), список кредитов с остатком, статусом, визитами и сроком;
    «Пополнить» открывает шит.
  - `showClientCreditSheet` — создание (вид, сумма, посещения, срок, заметка)
    и карточка кредита: «Списать», «Вернуть остаток», «Удалить» + история
    движений из аудита (`_HistoryRow` с `+/−`).
  - `showUseCreditSheet(credit, jobId:, maxCents:)` — сумма и посещения;
    подпись, что списание не трогает кассу.
  - `ClientCreditsScreen` — экран «Обязательства» (итого, активных, истекло)
    со списком всех кредитов и переходом к клиенту.
  - «Любимые позиции» — `KeyValueRow` с top-3 **независимо от флага**:
    считается частота заказов, а не строк (`store.favoritePositions`),
    позиции из каталога берутся по имени каталога.
- `client_detail_screen` — вставка `ClientMoneySection(clientId:)` после
  кнопки-чипов; `money_screen` — плитка «Обязательства перед клиентами»
  (видна при включённом флаге и ненулевом остатке) → `ClientCreditsScreen`.
- `job_detail_screen` — `_payFromCredit` в начале `_closeJob`: если у клиента
  есть активные кредиты, при закрытии заказа сначала предлагается списать их
  (sheet с суммой и визитами, `maxCents` = остаток к оплате); после полного
  покрытия заказ закрывается, иначе возвращается к обычному диалогу оплаты.
- Флаг `module_credits` (`settings.creditsEnabled`, по умолчанию **выключен** —
  как `module_leads`) + переключатель «Депозиты и сертификаты» в «Что показывать».

## Риски и ограничения
- Миграции нет, поэтому откат на 0.4.3 не трогает данные кредитов — таблица
  была в v22, старый билд просто её не читает.
- Аудит-история обрезана `limit = 2000` записей: при очень длинной истории
  ранние списания не попадут в Δ обязательств за старый период. Для
  локального масштаба мастеров запас многократный; при росте — параметр
  выбирается в одном месте (`AppDatabase.creditChanges`).
- Просроченный кредит остаётся на балансе: решение «вернуть или признать
  выручкой» за владельцем, как требует §5.5 п.3. Автоматического признания
  выручкой по сроку **нет**.
- Витрина «Сегодня» обязательства перед клиентами не показывает — агрегатор Э9.
- `locations_flag_test`, `metrics`, `dashboard_export` и остальные тесты
  следующих этапов — в финальной тестовой задаче плана.
