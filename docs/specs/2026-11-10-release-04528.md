## Состав релиза

### Э5.1 Схема и реестры (v25)
- `lib/data/app_database.dart` — `_createStockLocationsSchema()` (5 таблиц + индексы),
  `_ensurePurchaseReceiptColumns()` (идемпотентный `ALTER TABLE`), ветка `case 25` в
  `_upgradeSchema`. При первичном создании БД вызывается тем же путём.
- `lib/data/schema_tables.dart` — новые таблицы добавлены в `kSyncedTables`,
  `kBackupTables`, `kAuditedTables`, `kMojibakeScanColumns`, `kTableDependencies`,
  чтобы бэкап/синхронизация/аудит/лечение кодировки их не пропускали.
- `test/migration_upgrade_test.dart` — регрессия v1..v19 → **v25** с проверкой наличия
  пяти таблиц, `purchases.received_at`, `purchase_lines.received_qty`, плюс
  `integrity_check`/`foreign_key_check`.

### Э5.2 Модели
- `stock_location.dart` — `StockLocation`, `StockLevel` (остаток `item × location`).
- `stock_batch.dart` — `StockBatch` + `isExpiredAt(now)`, `isExpiringSoonAt(now, {days})`.
- `stock_transfer.dart` — `StockTransfer`, `StockTransferLine`.
- `supplier.dart` — `Purchase.receivedAt` + `copyTotal(int)`, `PurchaseLine.receivedQty`
  + `isShortAt`/`shortageQty` (недопоставка считается вслух).
- `production_need.dart` — `ProductionNeed` (потребность из состава изделия).
- `job_items.dart` — `JobStage.leadHours` (в `toMap`/`fromMap`/`copyWith`) для
  предупреждения о загрузке мощностей.

### Э5.3 Репозитории и `upsertRow`
- `stock_location_repository.dart`, `stock_batch_repository.dart`,
  `stock_transfer_repository.dart`.
- **`lib/data/repositories/upsert.dart` (новый)** — `upsertRow(db, table, row)`:
  `UPDATE` по `id`, `INSERT` если обновлено 0 строк. Заменил `ConflictAlgorithm.replace`
  во всех затронутых репозиториях: под `PRAGMA foreign_keys = ON` режим `replace`
  делает `DELETE` + `INSERT`, что роняет `ON DELETE RESTRICT` и каскады (приёмка
  закупки падала на второй сохранении той же строки).
- FEFO-сортировка вынесена в константу `_fefo`
  (`(expires_at IS NULL) ASC, expires_at ASC, created_at ASC`) — сначала партии с
  ближайшим сроком, партии без срока годности в конце.

### Э5.4 Стор: остатки, партии, перемещения, приёмка
- Геттеры `locations`, `stockLevels`, `batches`, `transfers`, `purchases`;
  репозитории `_locationRepo/_batchRepo/_transferRepo`, загрузка в `load()`.
- `adjustStock(..., {expiresAt, purchaseId, locationId})` — единая точка входа
  движения: под флагом рождает/списывает партии и пересчитывает `stock_levels`,
  без флага — прежнее поведение по одному складу.
- Точки: `ensureDefaultLocation`, `setLocationsEnabled`, `createLocation`,
  `updateLocation`, `deleteLocation` (последнюю точку не удаляем), `locationName`.
- Остатки и сроки: `stockBatches`, `stockOnLocation`, `minQtyOnLocation`,
  `setMinQtyOnLocation`, `belowMinOnLocation`, `expiringBatches`, `nearestBatch`.
  `minQtyOnLocation` различает «порог на точке = 0» и «порог не задан» (тогда
  берётся общий `item.minQty`).
- Приёмка: `receivedForPurchase`, `receivePurchase` — приход партиями на выбранную
  точку с указанным сроком годности; принятый объём меньше заказанного = недопоставка,
  долг поставщику пересчитывается по факту приёмки (`copyTotal`), а не по заказу.
- Перемещения: `createStockTransfer` (списание FEFO с одной точки, приход на другую по
  той же себестоимости), `transferLines`.
- План производства: `productionPlan` (потребность из состава изделия с учётом остатков
  на точке и минимумов), `_expandComposition`, `createPurchaseFromPlan`,
  `capacityWarning` (загрузка по `stage.leadHours`).
- `createPurchase` под включённым флагом **не** делает приход: приход рождает приёмка,
  иначе недопоставка «пришла» бы на склад в полном объёме.

### Э5.5 Флаг и UI
- `settings_controller.dart` — `locationsEnabled` (default `false`) + `setLocationsEnabled`.
- `settings_screen.dart` — переключатель «Несколько точек» с подтверждением
  (включение создаёт точку «Основная» и разносит текущие остатки на неё).
- `inventory/locations_screen.dart` — список точек, остатки, истекающие/просроченные
  партии, порог на точке, действия.
- `inventory/stock_transfer_screen.dart` — перемещение между точками (FEFO-подсказки).
- `inventory/purchase_receipt_screen.dart` — приёмка: «заказано / принято /
  недопоставка» и новый долг поставщику, срок годности партии.
- `inventory_screen.dart` — вход в Э5 под флагом: карточка «Точки» со счётчиком
  истекающих партий и чипами «Перемещение»/«Приёмка» + пункты в меню.
- `masters_store.supplierById` / `supplierName` — имена поставщика в приёмке.

## Риски и ограничения
- Флаг выключен по умолчанию: у существующих пользователей схема обновится, но
  поведение склада не изменится до явного включения.
- При включении флага текущий `item.stockQty` переносится на точку «Основная»
  одной партией без срока годности;history движений не переписывается.
- Себестоимость при перемещении берётся FEFO-средней с точки-источника; разница
  между точками в ценах закупки не отражается (нет разреза себестоимости по точкам).
- Периодически `rebuildLevels` пересобирает `stock_levels` из партий; если данные
  разошлись (ручная правка БД), остатки берутся из партий — это ожидаемо.
- `capacityWarning` — эвристика по `leadHours` стадий, не учёт персонала (Э7).
