# Masters Web — состояние и заметки

## Коротко

Web-версия запускается: `http://localhost:8080`, база SQLite (WASM) хранится
в IndexedDB, данные переживают перезагрузку страницы. Вход в Яндекс Диск
выполняется через OAuth в браузере — логин и пароль приложение не видит.

## Платформы

- Android / iOS — мобильное приложение;
- Windows — десктоп;
- Web — браузерная версия (локальный Dart-сервер).

## Что было починено в web-сборке

1. **Несовместимый `sqlite3.wasm`.** `dart run sqflite_common_ffi_web:setup`
   по умолчанию качает wasm из ветки, не совпадающей с Dart-пакетом `sqlite3`.
   Теперь используется `sqlite3-3.5.2/sqlite3.wasm`, совпадающий с `sqlite3 3.5.2`.
   Проверка совместимости: `WebAssembly.Module.exports()` должен содержать
   `sqlite3_initialize`, а импорты — только `dart:*` (без `env.memory`).
2. **`sqflite_common_ffi_web` обновлён до 1.2.0** (было 0.4.5+4) — в новой
   версии исправлена работа VFS/IndexedDB и добавлена защита от открытия
   одного файла дважды.
3. **`PRAGMA foreign_keys = ON`** не выполняется на web (в wasm-сборке
   прагма при открытии соединения даёт `SQL logic error`).
4. **`newId()`**: `Random().nextInt(1 << 32)` на web падает с
   `RangeError: max must be in range 0 < max ≤ 2^32` (JS-сдвиг 32-битный).
   Заменено на два 30-битных значения.
5. Режим фабрики: `databaseFactoryFfiWebNoWebWorker` — без web worker,
   проще отлаживать; для объёма данных приложения скорости хватает.

## Яндекс Диск: вход без логина и пароля

Подробная инструкция — в `docs/YANDEX_OAUTH.md`.

- `lib/core/yandex_oauth.dart` — authorization code flow с PKCE, токен и
  refresh-токен в `shared_preferences`;
- `lib/core/yandex_disk_service.dart` — REST API Диска
  (`cloud-api.yandex.net`), файл `disk:/Masters/masters-backup-latest.json`;
- `web_server/server.dart` — прокси `/api/oauth/token`, `/api/disk/*`,
  `/api/upload`, `/api/fetch` (обход CORS, токены не хранит, `client_secret`
  добавляет только сервер из переменной окружения);
- экран настроек: «Войти через Яндекс», статус подключения, загрузка и
  восстановление бэкапа, автобэкап при запуске.

ClientID задаётся при сборке:

```bat
set YANDEX_CLIENT_ID=ваш_client_id
set YANDEX_CLIENT_SECRET=ваш_client_secret
flutter build web --release --no-web-resources-cdn --no-wasm-dry-run --dart-define=YANDEX_CLIENT_ID=%YANDEX_CLIENT_ID%
```

`launch_masters.bat` подставляет переменные автоматически.

## Формат синхронизации: JSON

- `MastersStore.backupData()` отдаёт полный снимок всех таблиц с версией
  формата; `restoreFromBackup()` принимает его обратно без потерь.
- Один и тот же файл `masters-backup-latest.json` читают веб-версия и Android.
- **CSV для синхронизации не используется**: он плоский (только заказы),
  теряет связи, типы и вложенные сущности. Оставлен только как ручная
  выгрузка «для Excel» (`Экспорт CSV` в настройках) и на синхронизацию
  не влияет — при желании его можно удалить без последствий для бэкапов.

## Сборка и запуск

```bat
flutter pub get
flutter build web --release --no-web-resources-cdn --no-wasm-dry-run
dart run web_server/server.dart 8080
```

Ярлык «Masters Web» на рабочем столе запускает `launch_masters.bat`
(первый запуск собирает проект, `--rebuild` — пересобрать принудительно).

## Известные ограничения

- Redirect URI OAuth привязан к `http://localhost:8080/oauth/yandex`:
  при смене порта нужно обновить и приложение в Яндекс ID, и
  `_webRedirect` в `lib/core/yandex_oauth.dart`.
- Токен лежит в `shared_preferences` (localStorage) — это компромисс:
  пароль не хранится, но токен доступен скриптам этой же страницы.
- Синхронизация пока «снимок целиком» (кто последний загрузил, тот и прав),
  без слияния изменений по записям.

## Синхронизация

4. **Автозагрузка при старте есть, автозагрузки (pull) нет.** Сейчас при
   запуске только выгружается снимок. Нужно решить, как подтягивать
   изменения с другого устройства: по `exported_at` (кто новее) или иначе.
5. **Нет слияния по записям.** При работе на двух устройствах возможна
   потеря изменений: последняя загрузка перезаписывает всё. Варианты:
   сравнивать `updated_at` по каждой таблице, либо перейти на журнал
   операций (oplog).
6. **Нет разрешения конфликтов в UI** — пользователь не видит, что его
   локальные данные старше облачных.

## Web-платформа

7. **Несколько вкладок.** SQLite-база в IndexedDB открывается один раз на
   страницу (`singleInstance: false` на web запрещён). Две вкладки с
   приложением могут писать в один файл — нужен `BroadcastChannel`-лок или
   предупреждение «приложение уже открыто».
8. **Очистка данных браузера = потеря базы.** Стоит показывать напоминание
   о бэкапе (например, баннер, если Yandex не подключён, а данные есть).
9. **`sqlite3.wasm` зафиксирован вручную.** `dart run sqflite_common_ffi_web:setup`
   перезапишет его версией 3.6.0, несовместимой с `sqlite3 3.5.2` в
   `pubspec.lock`. Нужно либо обновить пакет `sqlite3`, либо добавить
   проверку версии в `launch_masters.bat`.

## Мобильные/десктопные сборки

11. **`client_secret` в мобильном бинарнике** извлекаем. Для продакшена
