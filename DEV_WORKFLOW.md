# Masters — параллельная разработка (телефон + веб)

## Принципы

- **Один код для всех платформ.** Никаких `dart:io`/`dart:html` в общей логике;
  платформенные различия идут через условные импорты `dart.library.*` и
  `kIsWeb`, как в `yandex_disk_service.dart`, `main.dart`, `web_url.dart`.
- **Единый источник конфигов.** `dart_defines.json` (gitignored) питает и
  web, и android через `--dart-define-from-file`. Шаблон:
  `dart_defines.example.json`. Не коммитьте реальные ClientID/Secret.
- **Секреты остаются на сервере/в env.** На web `YANDEX_CLIENT_SECRET`
  подставляет `web_server/proxy_server.dart` из переменной окружения.
- **Мобильные сборки не трогают wasm.** `web/sqlite3.wasm` и `sqflite_sw.js`
  фиксированы под `sqlite3 3.5.2`; не запускайте `sqflite_common_ffi_web:setup`,
  он перезапишет неподходящий бинарник. При необходимости —
  `launch_masters.bat --rebuild` или см. `WEB_HANDOFF.md`.

## Три сценария работы

### 1. Веб с горячей перезагрузкой (для UI)

```bat
scripts\dev_web.bat
```

1. Запускает прокси Яндекса на `:8081` (окно в отдельном процессе).
2. Запускает `flutter run -d web-server --web-port 8080` — изменения в
   `lib/` подхватываются через горячую перезагрузку (web: горячий рестарт,
   обычно 1–3 с).
3. Откройте `http://localhost:8080` в вашем браузере. Данные (IndexedDB)
   сохраняются между рестартами, удобно тестировать сценарии.
4. OAuth-редирект `http://localhost:8080/oauth/yandex` настроен именно на
   этот порт — `YANDEX_API_BASE=http://localhost:8081` нужно только для API.

### 2. Android параллельно

В другом терминале:

```bat
scripts\dev_android.bat            # первое найденное устройство
scripts\dev_android.bat emulator-5554   # конкретное
```

Android использует ту же базу кода; активный выбранный web-процесс при этом
останавливать не нужно. Горячая перезагрузка в терминале Android
независима.

VS Code: compound `Web+Android (parallel)` запускает обе одновременно;
перед этим выполните `scripts/dev_web.bat` (только прокси) или оставьте его
работающим, иначе API-вызовы на `:8081` упадут.

### 3. Финальные артефакты обоих платформ

```bat
scripts\build_all.bat
```

Соберёт web-release в `build/web/` и APK в
`build/app/outputs/flutter-apk/app-release.apk`.

## Единный workflow для скрытых настроек

- Секреты и ClientID не коммитим. В репозитории только шаблон
  `dart_defines.example.json`. Скопируйте в `dart_defines.json` и заполните.
- Сервер читает `YANDEX_CLIENT_SECRET` из окружения при каждом запуске —
  значит, менять секрет можно без пересборки приложения.

## Что нельзя запускать параллельно

- `flutter run -d chrome` открывает отдельное окно Chrome с временным
  профилем: IndexedDB между запусками не сохраняется, использовать
  только для быстрых UI-проверок.
- Два процесса на порту 8080 конфликтуют: либо dev-сервер (`:8080`),
  либо продакшен `web_server/server.dart` (`:8080`), но не оба.
- Файл `web/sqlite3.wasm` нельзя перезаписывать «своим» путём —
  он зафиксирован под `sqlite3 3.5.2`.
- Миграции БД: при изменении схемы обновляйте `onCreate`, `onUpgrade` и
  `restoreFromBackup()`; иначе веб- и мобильные данные разойдутся.
- `dart run sqflite_common_ffi_web:setup` запускать только если удалили
  файлы wasm/sw.

## Быстрая проверка

- `flutter analyze --no-pub` — должно быть ≤ 11 info (только `print` в
  серверном скрипте).
- `flutter test` — 2 теста, 3 проверки.
- Ручной чек перед коммитом: добавить запись в браузере → перезапустить
  страницу → запись на месте; загрузить/восстановить бэкап через Яндекс.
